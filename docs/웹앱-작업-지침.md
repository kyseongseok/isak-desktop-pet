# 휴대폰 웹앱 작업 지침

이삭이 미니게임을 아이폰·안드로이드에서 하는 **웹앱**으로 만드는 작업의 방향과 지켜야 할 것.
2026-10-26, 데스크톱 펫 세션에서 사용자와 정한 내용을 정리한 문서예요. 할 일 체크리스트는 [향후-과제.md](향후-과제.md)의 "휴대폰 웹앱" 항목.

> 이 작업은 데스크톱 펫과 **다른 세션**에서 진행해요. 펫 세션도 같은 저장소의 게임 파일을 계속 고칠 수 있으니, 아래 "지켜야 할 것"을 꼭 봐 주세요.

## 1. 목표

- **누가**: 사용자의 가족·지인 (회사 밖). 회사 PC의 데스크톱 펫과는 별개
- **어떻게 공유**: 링크 하나 → 휴대폰 브라우저에서 열고 **"홈 화면에 추가"** → 아이콘으로 전체 화면 실행
- **왜 웹앱인가**: 아이폰은 앱 스토어(개발자 등록 연 $99) 없이 앱 파일을 나눌 방법이 없음. 웹앱은 아이폰·안드로이드 둘 다 링크로 해결
- **완료 기준**
  - 아이폰 사파리·안드로이드 크롬에서 게임 4종을 터치만으로 끝까지 플레이
  - 최고 기록·최근 기록·카드 이름이 휴대폰에 저장되고, 다시 열어도 남아 있음
  - 홈 화면 아이콘으로 열면 주소창 없이 전체 화면, 한 번 연 뒤엔 인터넷 없이도 실행
  - 점수 카드 저장·공유가 휴대폰에서 됨
  - **데스크톱 펫 앱과 맥용 IsakGames가 예전처럼 그대로 돌아감**

## 2. 이미 정한 것

| 항목 | 결정 |
|---|---|
| 넣을 게임 | 🍎 과수원을 지켜라 · 🍉 이삭이 쑥쑥 · 🧺 이삭이 수확팡 · 🏃 이삭RUN (4종) |
| 뺄 게임 | ⌨️ 이삭이 타자게임 — 휴대폰 자판이 화면 절반을 가리고 한글 입력(조합 중 글자)이 까다로움 |
| 코인 | 없음, 무료 (맥용 IsakGames와 같음) |
| 진동 | 넣음. 안드로이드만 동작(사파리는 진동 미지원). 설정에 켜기/끄기 + "아이폰은 기기 특성상 진동이 지원되지 않을 수 있어요" 안내 |
| 공개 순위표 | 선택 작업. 하게 되면 구글 시트 + 앱스 스크립트, 가벼운 검사만 (아래 6장) |
| 올릴 곳 | GitHub Pages 후보 (저장소 `kyseongseok/isak-desktop-pet`, 이미 공개 저장소) |
| 안드로이드 APK | 선택 작업. 웹앱 완성 뒤 Capacitor로 감싸기 |

## 3. 게임별 터치 조작

지금 게임은 키보드 위주예요. 게임 규칙은 건드리지 말고 **입력만 추가**해 주세요.

| 게임 | 지금 | 휴대폰에서 |
|---|---|---|
| 과수원을 지켜라 (`app/game`) | ← → | 화면 왼쪽/오른쪽 절반을 누르고 있으면 그쪽으로 이동, 또는 손가락을 따라 이동 (해 보고 나은 쪽) |
| 쑥쑥 (`app/merge`) | ← → 조준 + Space | 손가락을 대고 끌어서 조준, **떼면 떨어뜨림** |
| 수확팡 (`app/pang`) | 마우스 끌기·클릭 | pointer 이벤트라 거의 그대로. 캔버스에 `touch-action: none`만 (끌 때 화면이 스크롤되지 않게) |
| 이삭RUN (`app/runner`) | Space/클릭 (길게 = 높이, 2단 점프) | pointerdown/up이라 거의 그대로. `touch-action: none`, 길게 누를 때 뜨는 메뉴·글자 선택 막기 |

**모든 게임 공통으로 확인할 것**
- 첫 화면이 "PRESS SPACE"뿐 — **화면을 눌러 시작**할 수 있어야 함 (휴대폰에선 "TAP TO START")
- 결과 화면의 다시 하기·게임 방법(❓) 페이지는 이미 버튼이 있음
- 페이지에 `<meta name="viewport">`가 없음 → 추가해야 휴대폰에서 제 크기로 보임. 무대(480×800)는 각 게임의 `fitStage()`가 화면에 맞춰 줄여 줌
- 아이폰 노치·홈 바 영역(safe area)에 버튼이 가리지 않게
- 효과음: 웹 오디오는 첫 터치 뒤에 소리가 남 (게임 시작을 누르니 대부분 문제없음). 아이폰 무음 스위치를 켜 두면 소리 안 남

## 4. 구조: 지금 있는 걸 어떻게 재활용하나

- **게임은 이미 브리지(`window.game`)로만 바깥과 이야기함.** Electron에선 `app/game/preload.js`가 넣어 주고, 없으면 각 `game.js` 맨 위의 가짜 브리지를 씀(브라우저 미리보기용, **저장이 안 됨**)
  → 웹용 브리지 파일을 하나 만들어 게임보다 먼저 불러오면 됨: 최고 기록·기록·이름을 브라우저 저장소(localStorage)에, `getCoins()`는 `{ free: true }`(코인 문구는 `card.js`의 `coinText` / `retryText`가 처리), `close()`는 게임 고르는 화면으로 이동
- **점수 카드**: `app/game/card.js` (다섯 게임 공용). 이름 칸·카드 그림·코인 문구. 휴대폰에선 `bridge.shareCard()`를 **공유 시트**(`navigator.share`, 파일 공유)로, 안 되면 이미지 내려받기로
- **게임 고르는 화면**: `app/arcade/index.html` + `menu.js` (맥용 앱). `window.arcade.list()` / `open()`을 웹용으로 바꿔 끼우면 재활용 가능
- **그림·글꼴 경로**: 게임들이 `../game/img`, `../game/font`, `../renderer/img`(점수 카드의 이삭이 포즈), `../runner/img`처럼 서로의 폴더를 참조함 → 웹으로 묶을 때 폴더 구조를 유지해야 함
- **CSP**: 각 `index.html`에 `default-src 'self'`가 있음. 순위표로 바깥 주소에 요청하려면 `connect-src`를 열어야 함
- **권장 방식**: `app/`을 직접 웹용으로 바꾸지 말고, 빌드 스크립트(예: `tools/build-web.*`)가 필요한 폴더를 `dist-web/`에 복사하면서 viewport·웹 브리지·매니페스트·서비스 워커를 끼워 넣는 쪽. 그래야 Electron 쪽이 웹 때문에 깨질 일이 적음. 최종 방식은 작업 세션이 판단
- **설치 파일 크기**: 배경 그림은 JPG로 줄여 둔 상태(장당 ~100KB). 휴대폰용으로 더 줄여도 됨

## 5. 지켜야 할 것

1. **데스크톱 펫이 깨지면 안 됨.** 게임 파일(`app/game`, `app/merge`, `app/pang`, `app/runner`, `app/game/card.js`, `app/game/preload.js`)은 펫 앱과 맥용 IsakGames가 같이 씀
   - 게임 규칙·점수·난이도는 바꾸지 않기 (펫 세션에서 조정 중일 수 있음). 터치 입력은 **추가**만
   - 고친 뒤 확인: 펫 앱(`ISAK_COINS=5 ISAK_OPEN_GAME=runner npm start`, kind는 orchard|typing|merge|pang|runner), 맥용 앱(`electron app/arcade/main.js`)
   - 펫 세션과 같은 파일을 동시에 고칠 수 있으니 **자기 브랜치(워크트리)**에서 작업하고 합칠 때 충돌 확인
2. **회사 쪽과 연결하지 않기.** 회사는 망분리라 외부 서버를 쓸 수 없음. 순위표·웹앱은 휴대폰용으로만, 펫 앱 게임에는 넣지 않음
3. **공개하기 전에 사용자에게 확인.** GitHub Pages에 올리면 누구나 링크로 열 수 있음. 농촌진흥청 캐릭터(이삭이)를 회사 밖에 공개해도 되는지 사용자가 판단해야 함. 올리는 것 자체(외부 공개)도 사용자 승인 뒤에
4. **커밋·푸시는 사용자가 말할 때만.** 버전 번호도 사용자와 정하기
5. **설명·진행 안내는 전부 한국어로**

## 6. 공개 순위표 (선택)

- 정해진 방향: **구글 시트 + 앱스 스크립트**(무료). 게임이 점수를 보내면 스크립트가 시트에 한 줄 추가, 순위표를 열 때 시트를 읽어 보여 줌 → 여는 순간 최신 (켜 둔 화면이 저절로 바뀌지는 않음, 새로고침)
- 대상이 **가족·지인**이라 가벼운 검사만
  - 게임별로 나올 수 없는 점수 거르기
  - 점수와 플레이 기록(시간, 수확 수, 거리 등)이 서로 맞는지
  - 짧은 시간에 연달아 보내면 막기
  - 이상한 기록은 사용자가 시트에서 직접 지움
- 점수 조작은 완전히는 못 막음(휴대폰에서 계산해 보내는 구조). 사용자도 알고 동의한 부분
- 이름이 공개되니 별명 쓰도록 안내
- 앱스 스크립트 주소는 사실상 공개 주소가 됨. 스크립트 배포·시트 만들기는 사용자 구글 계정이 필요하니 사용자와 같이

- 진동·홈 화면 추가·오프라인은 **실제 휴대폰**에서만 확인 가능 → 사용자에게 부탁. 아이폰·안드로이드 각각
- 같은 와이파이의 휴대폰에서 맥의 미리보기 서버로 접속해 보는 것도 방법 (단, 서비스 워커는 https나 localhost에서만 동작)
